# 실데이터 확보·적재 가이드

이 서비스는 **4-05 와이파이 AP별 이용 현황**과 **3-04 버스 정류소별 이용 현황**을 필수로 쓰고, 나머지 7종(4-01·4-06·3-02·3-01·3-03·5-02·5-01)은 있으면 쓰고 없으면 해당 기능만 비활성화됩니다. 아래 순서대로 하면 10분 안에 끝납니다.

## 1. 다운로드 (제주데이터허브 — 1순위)

1. https://jejudatahub.net 로그인 → 상단 **제주빅데이터센터** 메뉴 → **데이터 명세** (https://jejudatahub.net/center/data)
2. 명세서 번호로 찾기: `4-05`, `3-04` (필수) → `3-03`, `3-01`, `3-02`, `5-02`, `5-01`, `4-01`, `4-06` (권장)
3. 각 데이터의 **다운로드(CSV)** 버튼으로 받습니다. 기간 선택이 있으면 **최근 3~6개월**이면 충분합니다(와이파이 4-05는 한 달에 수십만 행이라 6개월을 넘기면 노트북에서 느려집니다).
4. 다운로드 버튼이 없고 "센터 방문 제공"으로만 표시되는 데이터는 §4를 보세요.

> 운영진 답변(2026-10-30): 센터 데이터 시스템에 Agent가 API로 직접 붙는 방식은 지원하지 않고, **CSV 반입**만 가능합니다. 그래서 이 서비스는 처음부터 CSV 적재 방식입니다.

## 2. 넣기

받은 파일을 **그대로** `data/raw/` 에 복사하세요. 파일명은 아래 중 아무거나로 시작하면 자동 인식됩니다.

| 데이터 | 인식되는 파일명 예 |
|---|---|
| 4-05 | `와이파이 AP별 이용 현황.csv`, `4-05 와이파이 AP별 이용 현황_202507.csv`, `wifi_ap_usage.csv`, 폴더 `data/raw/wifi_ap_usage/*.csv` |
| 3-04 | `버스 정류소별 이용 현황.csv`, `3-04_버스정류소별이용현황.csv`, `bus_station_usage.xlsx` |
| 그 외 | `config/schemas.yaml` 의 `name`·`code`·키 중 하나로 시작 |

지원 형식: `.csv` `.tsv` `.txt` `.xlsx`. 인코딩(utf-8/cp949/euc-kr)과 구분자(쉼표/탭/세미콜론)는 자동 판별합니다. 헤더는 명세서의 영문명·한글명 어느 쪽이든 되고, 조금 달라도(`정류장명`, `승차인원수`, `기준일자` 등) `config/column_aliases.yaml` 의 별칭 규칙으로 맞춥니다.

## 3. 확인

```bash
python scripts/check_data.py          # 인식 결과·헤더 매핑·기간·행 수 표
python scripts/check_data.py --strict # 필수 2종이 실데이터가 아니면 종료코드 1 (CI·제출 전 점검용)
```

출력에서 볼 것:
- `source` 가 `raw` 인지 (synthetic이면 파일명이 인식되지 않은 것 → §2 표대로 이름 변경)
- `note` 의 **별칭 매핑 / 기본값 채움** — 기본값으로 채운 컬럼(예: `get_on_off_type=승차`)은 원본에 없던 값이므로 해석 시 그 사실을 압니다. UI 사이드바 "적재 데이터"와 답변의 **한계** 항목에 자동으로 표시됩니다.
- `값이 전부 비어 있는 필수 컬럼` 경고가 있으면 헤더가 매핑되지 않은 것 → `column_aliases.yaml` 에 별칭 한 줄 추가

그다음 샘플·그림·기획서를 실데이터로 다시 만듭니다.

```bash
python -m jeju_agent.cli --offline --batch examples/questions.txt --out outputs/samples/batch_offline.json
python -m jeju_agent.cli --batch examples/questions.txt --out outputs/samples/batch_llm.json   # .env 에 API 키가 있을 때
python -m jeju_agent.cli --offline --png "효율이 낮은 버스 노선은?"                              # docs/img 갱신용 PNG
python scripts/make_submission.py                                                               # ZIP·PDF 재생성
```

## 4. 허브에서 바로 받을 수 없을 때 (대안, 2순위)

공공데이터포털(data.go.kr)에 제주특별자치도가 같은 계열의 데이터를 올려 두었습니다. 구조가 명세서와 다르지만 별칭 규칙으로 읽힙니다. 단, **대회 필수 데이터 요건은 제주빅데이터센터·제주데이터허브 데이터**이므로 아래는 개발·시연용 보조로만 쓰고, 최종 제출 전에는 반드시 허브 데이터 1종 이상(가능하면 4-05·3-04)을 적재하세요.

| 대체 데이터 (data.go.kr) | 대응 | 비고 |
|---|---|---|
| [제주특별자치도_일별 시간대별 버스 승차 인원 수 현황 (2019)](https://www.data.go.kr/data/15094729/fileData.do) | 3-04 | 승차만 있음 → `get_on_off_type=승차`, `user_category=일반` 기본값으로 채워짐(교통약자 비중 기능은 의미 없음) |
| [제주특별자치도_와이파이 장소별 사용자 현황 (2018.1~2020.11)](https://www.data.go.kr/data/15094747/fileData.do) | 4-05 보조 | 장소·연령·성별로 **이미 집계된** 자료라 고유 user_id 기반 혼잡지수는 계산되지 않음. `wifi_daily_users` 류 추세 보조로만 사용 |
| [제주특별자치도_와이파이 유형별 사용량 현황 (2018~2020)](https://www.data.go.kr/data/15094750/fileData.do) | 참고 | 유형별 집계 |

파일을 `data/raw/버스 정류소별 이용 현황_2019.csv` 처럼 이름 바꿔 넣으면 됩니다.

## 5. 센터 방문 제공 데이터

허브에 다운로드 버튼이 없는 데이터는 제주빅데이터센터(제주테크노파크)에 방문해 반출 신청 후 CSV로 받을 수 있습니다. 이 서비스가 쓰는 9종은 명세서상 모두 "데이터 반출 가능"이므로, 방문 시 코드 번호(4-05, 3-04 …)와 기간을 말하면 됩니다. 센터 PC에서 실행할 때는 `data/raw/` 대신 센터가 지정한 폴더를 `.env` 의 `JEJU_DATA_DIR` 로 가리키면 됩니다.

## 6. 자주 겪는 문제

| 증상 | 원인·해결 |
|---|---|
| `source=synthetic` 그대로 | 파일명이 인식 안 됨 → §2 표대로 이름 변경 후 "데이터 다시 읽기" |
| 행은 읽었는데 기간이 비어 있음 | 날짜 컬럼 매핑 실패 → `check_data.py` 의 "매핑되지 않은 원본 헤더"를 보고 `column_aliases.yaml` 의 `base_date` 별칭에 추가 |
| 혼잡 순위가 비어 있음 | 4-05 의 `user_id`·`ap_place` 가 비어 있음(집계본을 넣은 경우) → 허브의 원본 4-05 필요 |
| 메모리 부족 | 4-05 는 월 단위 파일로 나눠 받고 최근 3개월만 넣기. DuckDB 설치 시(`pip install duckdb`) 메모리 사용량이 줄어듦 |
| 한글 깨짐 | 자동 판별 실패. 엑셀에서 "CSV UTF-8"로 다시 저장 |
