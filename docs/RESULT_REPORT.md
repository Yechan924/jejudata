# 결과 설명자료 — 제주 혼잡·이동 진단 Agent

팀 재주도좋다 · v0.3 · 2026.11

## 1. 문제 정의
- 2026년 제주: 내국인 관광객 감소(9월 −8.1%), 외국인 급증(+18.1%), 특정 관광지 쏠림, 버스 준공영제 효율 논란.
- 도민·공무원이 "어디에 누가 몰리는가", "어느 노선·시간대가 비는가"를 직접 확인하려면 SQL·시각화 전문 인력이 필요.
- 센터의 유동인구·카드 데이터는 반출 불가 → **반출 가능 데이터만으로** 답할 수 있어야 누구나 어디서나 쓸 수 있다.

## 2. Agent 구조
```
질문(+최근 대화) → 플래너(LLM 도구호출 | 규칙 기반) → 분석 도구 12개(집계만) → 반출 게이트 → 해설(LLM | 템플릿) → 숫자 검증 → 자동 점검·후속 질문 → UI/리포트
```
- **플래너**: 시스템 프롬프트(스키마·도구 선택표·답변 형식·원칙) + JSON Schema 도구 12개. 도구를 부르기 전 계획 한 문장을 쓰게 하고 이를 🧭 실행 계획 패널에 노출. 최대 6회 호출, 오류 시 1회 재시도, 429/5xx 재시도, LLM 장애 시 규칙 모드로 폴백(폴백 사실도 계획에 표시).
- **도구(12)**: congestion_rank, place_profile, list_places, place_access, bus_station_rank, bus_route_efficiency, hourly_profile, weather_effect, congestion_forecast(주말 혼잡 예측), monthly_brief(월간 브리핑), run_sql(읽기 전용 집계), describe_data.
- **게이트**: 식별자 컬럼 제거, 10 미만 셀 마스킹(센터 반출 정책 기준), 500행 상한, 원본 행 차단. 차트는 PNG로 반출.
- **검증**: LLM 답변 숫자를 근거표와 대조(불일치 시 템플릿 대체), LLM 전송 내용 미리보기 탭, 출처 표기 상시.
- **해설**: 결론 / 근거 / 해석·제안 / 한계 4단. 합성 데이터 사용 시 경고 강제.
- **자동 점검(`insight.py`)**: 데이터 출처(실/합성/기본값 채움)·요청 기간과 적재 범위 차이·마스킹·표본 일수·검증 결과를 코드가 모아 한계에 붙임. **이어서 물어보기**: 결과의 1위 장소·정류소를 넣은 후속 질문 3개 제안. 최근 3턴을 맥락으로 전달해 지시어 해석.
- **적재(`data/loader.py` + `config/column_aliases.yaml`)**: 헤더 정확 일치 → 별칭 매칭 → 데이터셋별 기본값 순으로 표준화하고 매핑 이력을 provenance에 남김. CSV/XLSX, 인코딩·구분자·날짜 포맷 자동. `scripts/check_data.py`로 점검.
- 코드 위치: `jeju_agent/agent.py`, `insight.py`, `tools/`, `gate.py`, `llm.py`, `llm_mock.py`, `planner_rules.py`, `data/loader.py`.

## 3. 주요 기능
| 기능 | 질문 예 | 산출 |
|---|---|---|
| 혼잡 순위 | 주말에 가장 붐비는 관광지는? | 혼잡지수·관광/외국인 비중 순위, 지도 |
| 장소 프로필 | 성산일출봉은 언제 붐비나? | 일별·요일·월별, 구성비, 추세 |
| 관광지 접근 | 성산일출봉 가는 정류소는? | 반경 1.5km 정류소 승차·피크 |
| 노선 효율 | 효율 낮은 노선은? / 251번 시간대 | 승객/km/일, 저이용 시간대 |
| 교통약자 정류소 | 어르신이 많이 타는 정류소는? | 경로·장애 비중 순위, 시간대 |
| 강우 영향 | 비 오면 어디가 한산해지나? | 강우일/비강우일 변화율 |
| 주말 혼잡 예측 | 이번 주말 어디가 붐빌까? | 같은 요일 패턴×추세, 구간 제시 |
| 월간 브리핑 | 5월 월간 브리핑 | 혼잡·외국인·노선·강우 한 장 |
| 자유 집계 | 월정리 월별 이용자 | LLM 작성 집계 SQL |

## 4. 실행 결과 (합성 데이터, `examples/questions.txt` 14문항)
`python -m jeju_agent.cli --offline --batch examples/questions.txt` 실행 시 14문항 모두 응답(도구 오류 0건, 결과 `outputs/samples/batch_offline.json`에 계획·자동 점검·후속 질문 포함). 대표 결과:
- "주말에 가장 붐비는 관광지는?" → 성산일출봉, 주말 평균 혼잡지수 2.26(평일의 2.3배), 주변 정류소 1개 일평균 승차 74명, 피크 11시.
- "효율이 낮은 버스 노선은?" → 251번 1.56명/km/일, 저이용 시간대 6개(10~15시 집중).
- "비 오면 어디가 한산해지나?" → 애월한담해안 −56%, 실내형 오설록 +6%.
- "어르신이 많이 타는 정류소는?" → 대정읍사무소 경로 비중 37%(전체 평균 20%).
합성 데이터에 의도적으로 심은 패턴(성산 주말 급증, 251 낮 공차, 읍면 경로 비중, 해변 강우 민감)을 Agent가 모두 회수했다.
차트 예시: `docs/img/congestion.png`, `route251.png`, `rain.png`.

## 5. 검증 방법·한계
- pytest 43개 통과(API 키 불필요): 적재·한글/변형 헤더·기본값·XLSX·구분자·날짜 포맷·정보성 테이블 중복 제거, 도구 12종, 게이트 10 기준, 숫자 검증·환각 대체, PNG, SQL 차단, 오프라인 Agent·지시어 해석, 그리고 시나리오 LLM(`llm_mock.py`)으로 도구 호출 루프·오류 재시도·호출 한도·장애 폴백·대화 맥락·Anthropic 메시지 변환.
- LLM 실키 검증: `scripts/llm_smoke.py`가 문항별 도구 선택·숫자 검증·형식 준수를 `docs/LLM_EVAL.md`로 남김(키가 있는 환경에서 실행).
- 모든 답변에 도구 인자·계산 방법·게이트 로그가 붙어 수치를 역추적할 수 있다.
- 한계: 와이파이=표본(상대 지표), 4-05에 시각 없음, 버스 효율=승차 수요 기준, 강우 효과=단순 비교, 규칙 모드=정형 질문만, 후속 질문·자동 점검은 규칙 기반. **현 제출본은 합성 데이터로 검증**되었으며 실데이터 적재 시 임계값 보정 필요(절차: `docs/DATA_ACQUISITION.md`).

## 6. 센터 활용 방안
- 방문 상담 데스크: 상담원이 도민 질문을 그대로 입력해 즉석 리포트 제공.
- 관광·교통 부서 정기 브리핑: 배치 실행으로 주간 혼잡·노선 효율 요약 자동 생성.
- 확장: 비반출 데이터(카드·유동인구)를 같은 게이트 구조로 추가 → 센터 내부용 고해상도 버전.
