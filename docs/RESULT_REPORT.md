# 결과 설명자료 — 제주 혼잡·이동 진단 Agent

팀 재주도좋다 · v0.4 · 2026.11

## 1. 문제 정의
- 2026년 제주: 내국인 관광객 감소(9월 −8.1%), 외국인 급증(+18.1%), 특정 관광지 쏠림, 버스 준공영제 효율 논란.
- 도민·공무원이 "어디에 누가 몰리는가", "어느 노선·시간대가 비는가"를 직접 확인하려면 SQL·시각화 전문 인력이 필요.
- 센터의 유동인구·카드 데이터는 반출 불가 → **반출 가능 데이터만으로** 답할 수 있어야 누구나 어디서나 쓸 수 있다.

## 2. Agent 구조
```
질문(+최근 대화) → 플래너(LLM 도구호출 | 규칙 기반) → 분석 도구 13개(집계만) → 반출 게이트 → 해설(LLM | 템플릿) → 숫자 검증 → LLM 자기 점검·후속 질문(선택) → 자동 점검 → UI/리포트
```
- **플래너**: 시스템 프롬프트(스키마·도구 선택표·답변 형식·원칙) + JSON Schema 도구 13개. 도구를 부르기 전 계획 한 문장을 쓰게 하고 이를 🧭 실행 계획 패널에 노출. 최대 6회 호출, 오류 시 1회 재시도, 429/5xx 재시도, LLM 장애 시 규칙 모드로 폴백(폴백 사실도 계획에 표시).
- **도구(13)**: congestion_rank, place_profile, list_places, place_access, bus_station_rank, bus_route_efficiency, hourly_profile, weather_effect, congestion_forecast(주말 혼잡 예측), monthly_brief(월간 브리핑), **compare_periods(전반/후반·평일/주말·두 기간 비교, 2026-11-07 추가)**, run_sql(읽기 전용 집계), describe_data.
- **게이트**: 식별자 컬럼 제거, 10 미만 셀 마스킹(센터 반출 정책 기준), 500행 상한, 원본 행 차단. 차트는 PNG로 반출.
- **검증**: LLM 답변 숫자를 근거표와 대조(불일치 시 템플릿 대체), LLM 전송 내용 미리보기 탭, 출처 표기 상시.
- **해설**: 결론 / 근거 / 해석·제안 / 한계 4단. 합성 데이터 사용 시 경고 강제.
- **자동 점검(`insight.py`)**: 데이터 출처(실/합성/기본값 채움)·요청 기간과 적재 범위 차이·마스킹·표본 일수·검증 결과·이름 매핑 실패(좌표 없음)를 코드가 모아 한계에 붙임. **이어서 물어보기**: 결과의 1위 장소·정류소를 넣은 후속 질문 3개 제안. 최근 3턴을 맥락으로 전달해 지시어 해석.
- **LLM 부가 단계(`LLM_EXTRAS`, 2026-11-07 추가)**: 답변 뒤 ① `review` — LLM이 자기 답변을 근거 사실·주의 문구와 대조해 과장·인과 표현·오해 소지를 JSON으로 지적하면 자동 점검에 "LLM 자기 점검"으로 붙임, ② `followups` — 결과를 보고 다음 질문 3개를 제안(규칙 제안은 예비). 호출 1회씩 추가되며 파싱 실패·장애 시 규칙 기반으로 조용히 대체. 사이드바 체크박스로 제어.
- **적재(`data/loader.py` + `config/column_aliases.yaml`)**: 헤더 정확 일치 → 별칭 매칭 → 데이터셋별 기본값 순으로 표준화하고 매핑 이력을 provenance에 남김. CSV/XLSX, 인코딩·구분자·날짜 포맷 자동. 테이블 간 이름 연결은 정확 일치 → 정규화 키(공백·괄호·방향 꼬리표·일련번호 무시) → 유일 포함 관계 순. 실데이터와 기간이 겹치지 않는 합성 데이터는 섞지 않고 비활성 처리. `scripts/check_data.py`로 점검(매핑률·미연결 이름 상위 표시).
- 코드 위치: `jeju_agent/agent.py`, `insight.py`, `tools/`, `gate.py`, `llm.py`, `llm_mock.py`, `planner_rules.py`, `data/loader.py`.

## 3. 주요 기능
| 기능 | 질문 예 | 산출 |
|---|---|---|
| 혼잡 순위 | 주말에 가장 붐비는 관광지는? | 혼잡지수·관광/외국인 비중 순위, 지도 |
| 장소 프로필 | 성산일출봉은 언제 붐비나? | 일별·요일·월별, 구성비, 추세 |
| 관광지 접근 | 성산일출봉 가는 정류소는? | 반경 1.5km 정류소 승차·피크 |
| 노선 효율 | 효율 낮은 노선은? / 251번 시간대 | 승객/km/일, 저이용 시간대 |
| 교통약자 정류소 | 어르신이 많이 타는 정류소는? | 경로·장애 비중 순위, 시간대 |
| 강우 영향 | 비 오면 어디가 한산해지나? | 강우일/비강우일 변화율 |
| 주말 혼잡 예측 | 이번 주말 어디가 붐빌까? | 같은 요일 패턴×추세, 구간 제시 |
| 월간 브리핑 | 5월 월간 브리핑 | 혼잡·외국인·노선·강우 한 장 |
| 기간·요일 비교 | 9월 전반과 후반에 어디가 늘고 줄었어? / 평일과 주말 차이가 큰 정류소는? | 대상별 두 구간 일평균·변화율, 증가·감소 상위 |
| 자유 집계 | 월정리 월별 이용자 | LLM 작성 집계 SQL |

## 4. 실행 결과 (제주데이터허브 공개 API 실데이터 2025-09, `examples/questions.txt` 16문항)
`python -m jeju_agent.cli --offline --batch examples/questions.txt` → `outputs/samples/batch_offline.json` (계획·자동 점검·후속 질문 포함). 16문항 모두 정상 응답(날씨는 Open-Meteo 2025-09 재분석값, `data/demo/weather_*.csv.gz` 동봉). 대표 결과:
- "주말에 가장 붐비는 관광지는?" → 올레 19코스(주말 혼잡지수 2.03), 지하상가, 쇠소깍 해변 순(정류소·충전소 AP 제외, 관측 20일·일평균 20명 이상).
- "성산일출봉 가는 버스 정류소는?" → 반경 1.5km 정류소 14개, 합산 일평균 승차 518명(가장 가까운 성산일출봉입구 0.26km, 211명).
- "어르신이 많이 타는 정류소는?" → 장애인복지회관 96%, 서귀포향토오일시장 78%, 제주절물자연휴양림 77%(교통약자='기타' 요금제 포함).
- "효율이 낮은 버스 노선은?" → 295-4(성산항~서귀포) 0.27명/km/일; 최고는 360-1(부영아파트~제주대) 125명/km/일.
- "주말 승차 급증 정류소" → 렛츠런파크 3.6배, 관음사탐방로입구 2.3배, 한라생태숲 2.0배; 대학교·학교 정류소는 주말 0.
- "251번 노선" → 251 계열 6개 중 승차 최다 251-6: 일평균 171명(평일 191·주말 117).
- "비 오면 어디가 한산해지나?" → 강우일 기준을 1mm→**3mm로 자동 상향**(1mm로는 9월 관측소-일의 79%가 강우일) 후 관측소별 강우 16일/비강우 14일. 평일 감소폭 1위 탐라도서관(−96%, 41→2명), 방일리공원(−49%), 한라산 성판악탐방안내소(−40%); 반대로 제주항국제여객터미널(+83%)·올레 19코스(+122%)는 비 오는 날 평균이 높았다(상관, 요일·행사 미통제).
- "9월 전반과 후반에 어디가 늘고 줄었어?" → 전체 일평균 +2%, 최다 증가 서귀포의료원(31→46, +49%), 최다 감소 제주항국제여객터미널(197→75, −62%).
- "평일과 주말 차이가 큰 정류소는?" → 전체 −23%, 렛츠런파크 +216%(83→262), 제주한라대학교 −76%(476→115).
합성 데이터 단계에서 심어 둔 패턴(성산 주말 급증, 251 낮 공차, 읍면 경로 비중, 해변 강우 민감)은 모두 회수했고, 실데이터에서는 위처럼 현장과 부합하는 결과가 나온다.
차트: `docs/img/congestion.png`(주말 관광지 혼잡), `rain.png`(교통약자 정류소), `route251.png`(노선 효율).

### 4-1. 실데이터가 드러낸 문제와 수정 (2026-11-05)
| 문제 | 수정 |
|---|---|
| 관측 4일짜리 장소가 혼잡지수 31배로 1위 | 관측일(기간의 2/3)·일평균 20명 하한, 기준선 최소 10명 |
| 1,465개 장소 중 2/3가 정류소·충전소 AP | 관광지 질문에서 자동 제외, 장소명으로 카테고리 추론 |
| 와이파이 좌표 없음 | 4-01 장소명(75%) + 장소명 속 정류소ID→3-03(16%) 보완 |
| 3-04 정류소ID(7자리) ≠ 3-03(9자리) | 정류소명으로 매핑(86%) |
| 요금제에 '경로' 없음(일반/청소년/어린이/기타) | '기타'를 교통약자로 간주, 한계에 명시 |
| 시간대 컬럼 없음 | 시간대 질문을 일 단위 도구로 대체, 계획 패널에 사유 표시 |
| 제공처 날짜 공백(노선 9/21·23) | 자동 점검에 표시 |

### 4-2. 고도화 (2026-11-07)
| 항목 | 내용 |
|---|---|
| 날씨 실데이터 | `scripts/fetch_weather.py`: 기상청 기상자료개방포털 ASOS CSV 변환(관측값) / Open-Meteo(키 없음, 재분석; 브라우저 저장 JSON도 `--open-meteo-json`) / 기상청 API허브. 기상청 CSV를 변환 없이 넣어도 별칭으로 읽힘. 관측소 정보가 없으면 내장 제주 4개 지점(184·185·188·189) 사용. **2025-09 Open-Meteo 4개 지점 120행을 `data/demo`에 동봉**해 강우 문항이 바로 동작 |
| 강우 도구 보강 | `weather_effect`: 강우일 기준 자동 선택(강우일 비율 15~60%가 되는 1·3·5·10·20mm), 맑은 날 일평균 20 미만·강우/비강우 3일 미만 대상 제외, 정류소·충전소 AP 제외, 감소·증가 상위 각 10만 표시, 관측소 배정 벡터화(6.5초→0.1초). 월간 브리핑은 집계본에서 NaN 비중 대신 안내 문구, 시간대 없으면 승차 최저 노선으로 대체 |
| 합성 혼입 차단 | 핵심 데이터가 실데이터인데 기간이 겹치지 않는 합성 날씨·4-06이 있으면 적재하지 않고 "없음"으로 표시 → 강우 질문은 수집 방법을 안내하는 답변. 이전에는 2025-03~04 합성 강수량이 9월 실데이터와 섞여 오류를 냈음 |
| 이름 매핑 | 정류소명→3-03 ID: 정확 일치 + 정규화 키(공백·괄호·[동/서/남/북]·일련번호 무시) → 동봉 축약본 기준 **80% → 99%**(정류소명이 빈 8,132행은 같은 원본ID의 이름으로 복원). 와이파이 장소→좌표: 4-01 정규화·유일 포함 + 3-03 정류소ID·정류소명 → **91% → 93%**. 미연결 이름 상위는 check_data·자동 점검에 표시 |
| 기간 비교 도구 | `compare_periods`: 전반/후반, 평일/주말, 임의 두 기간을 장소·정류소·노선별로 비교(변화율 순, 증가·감소 상위 각 n). 규칙 플래너가 "비교·달라졌·늘었·줄었·전반·후반·차이"를 인식 |
| LLM 자기 점검·후속 질문 | `LLM_EXTRAS=review,followups`: 답변-근거 대조 지적을 자동 점검에 추가, 결과 기반 후속 질문을 LLM이 제안. 실패 시 규칙 대체 |
| 센터 PC 오프라인 LLM | Ollama 를 네이티브 `/api/chat`으로 호출해 `num_ctx`(기본 12,288)를 지정 — OpenAI 호환 `/v1`은 컨텍스트를 받지 못해 ~8k 토큰 프롬프트가 잘렸음. 로컬 모델에는 컬럼 목록을 생략한 압축 프롬프트. `scripts/ollama_check.py`가 서버·모델·도구 호출·Agent 질문을 순서대로 점검하고 tools 미지원 모델을 한국어로 안내 |

## 5. 검증 방법·한계
- pytest 57개 통과(API 키 불필요): 적재·한글/변형 헤더·기본값·XLSX·구분자·날짜 포맷·정보성 테이블 중복 제거, 도구 13종, 게이트 10 기준, 숫자 검증·환각 대체, PNG, SQL 차단, 오프라인 Agent·지시어 해석, 이름 정규화 매핑, 기상청 CSV 변환·직접 적재·합성 혼입 차단·실기간 강우 효과, 기간 비교 도구·규칙 라우팅, LLM 자기 점검·후속 질문과 실패 대체, Ollama 요청 형식·tools 미지원 안내, 그리고 시나리오 LLM(`llm_mock.py`)으로 도구 호출 루프·오류 재시도·호출 한도·장애 폴백·대화 맥락·Anthropic 메시지 변환.
