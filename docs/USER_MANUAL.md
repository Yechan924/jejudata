# 사용자 매뉴얼

## 1. 설치 (Windows 기준, 센터 PC)
1. Python 3.10 이상 설치(python.org, "Add to PATH" 체크).
2. ZIP을 풀고 `install.bat` 더블클릭(처음 한 번, 3~5분: 가상환경·패키지·합성데이터·테스트) → `run.bat` 더블클릭 → 브라우저에 UI.
3. macOS/Linux: `./install.sh` → `./run.sh`.

수동 설치: `python -m venv .venv` → `.venv\Scripts\activate` → `pip install -r requirements.txt` → `streamlit run app.py`

## 2. 데이터 넣기
- 제주데이터허브(jejudatahub.net) → 제주빅데이터센터 → 아래 데이터의 CSV를 내려받아 `data/raw/`에 복사하거나 UI 사이드바 "CSV 추가"로 업로드 후 "데이터 다시 읽기".
- 필수: 와이파이 AP별 이용 현황(4-05), 버스 정류소별 이용 현황(3-04). 권장: 버스 노선별 이용(3-02), 노선 정보(3-01), 정류소 정보(3-03), 일일 날씨(5-02), 관측소(5-01), 와이파이 AP 현황(4-01), 일별 이용자(4-06).
- 파일명은 한글 데이터명·코드·영문키 중 무엇으로 시작해도 됩니다. 기간별 파일 여러 개는 `data/raw/wifi_ap_usage/` 같은 폴더에 모아 두세요. CSV·XLSX 모두 되고, 헤더가 명세서와 조금 달라도(정류장명·승차인원수 등) 자동으로 맞춥니다.
- 넣은 뒤 `python scripts/check_data.py`로 인식·헤더 매핑·기간을 확인하세요. 자세한 절차와 대안 데이터는 `docs/DATA_ACQUISITION.md`.
- 날씨(강우 영향 질문용)는 허브에 없으므로 `python scripts/fetch_weather.py --kma-csv <기상청 CSV>`(기상자료개방포털 ASOS 일자료) 또는 `--open-meteo --from 2025-09-01 --to 2025-09-30`(키 없음)으로 받습니다. 없으면 "비 오면…" 질문에 수집 방법을 안내하는 답이 나옵니다.
- 실데이터가 없으면 `python -m jeju_agent.data.synthetic` 으로 개발용 합성 데이터를 만들 수 있습니다(모든 화면에 경고 표시).

## 3. LLM 설정 (선택)
`.env.example`을 `.env`로 복사하고 하나를 채웁니다.
- `ANTHROPIC_API_KEY=...` (기본 모델 claude-sonnet-5) 또는 `OPENAI_API_KEY=...`
- 외부망이 없으면(센터 PC) Ollama 설치(https://ollama.com/download) → 터미널에서 `ollama pull qwen2.5:7b` → `python scripts/ollama_check.py`로 서버·모델·도구 호출을 점검 → `.env`에 `LLM_PROVIDER=ollama`. 7b는 질문당 30~90초, 빠르게 보려면 `LLM_MODEL=qwen2.5:3b`. 점검 스크립트가 ❌를 내면 그 줄의 안내대로 하세요(모델 없음 → pull, tools 미지원 → 다른 모델).
- 아무것도 없으면 오프라인 규칙 모드로 동작합니다(사이드바 토글로 강제 가능).

## 4. 사용법
1. 사이드바 예시 질문 버튼을 누르거나 하단 입력창에 질문을 씁니다.
2. 답변 위 **🧭 Agent 실행 계획**을 펼치면 어떤 데이터를 어떤 순서로 왜 봤는지 보입니다. 답변은 한 줄 결론 → 근거 → 해석·제안 → 한계 순이며, 한계의 **자동 점검**은 코드가 데이터 출처·기간·마스킹을 확인해 적은 것입니다.
2-1. 답변 아래 **이어서 물어보기** 버튼을 누르면 결과에 맞는 다음 질문이 바로 실행됩니다. "거기 가는 버스는?"처럼 이어서 물어도 됩니다. LLM 모드에서는 사이드바의 **후속 질문 LLM 제안**·**답변 자기 점검** 체크로 LLM이 결과를 보고 다음 질문을 제안하거나 자기 답변을 근거와 대조해 지적(자동 점검에 "LLM 자기 점검")하게 할 수 있습니다(호출 1회씩 추가).
3. 탭에서 지도·차트·근거 표·방법/한계·실행 로그를 확인합니다.
4. "HTML 리포트"(PNG 차트 내장) 또는 "차트 PNG"로 결과를 저장·공유합니다. 반출 심사에는 PNG·리포트를 쓰세요.
5. "LLM 전송 내용" 탭에서 외부로 나간 내용을 확인할 수 있습니다. 답변 상단의 🔎 메모는 숫자 검증 결과입니다.
6. 센터 PC 퇴실 전 사이드바 "올린 자료 모두 삭제"를 누르세요.

예측·브리핑: "이번 주말 어디가 붐빌까?"(요일 패턴 기반 추정), "5월 월간 브리핑"(혼잡·외국인·노선·강우 한 장).
비교: "9월 전반과 후반에 어디가 늘고 줄었어?", "평일과 주말 차이가 큰 정류소는?", "2025-09-01~2025-09-07 와 2025-09-08~2025-09-14 노선 이용 비교".

질문 요령: 장소·노선은 일부만 써도 됩니다("성산", "251"). 기간은 "5월", "2025년 3월"처럼 쓰면 인식합니다. "주말", "외국인", "어르신", "비 오면" 같은 단어가 분석 조건이 됩니다.

## 5. 명령행
```
python -m jeju_agent.cli "질문"                         # 단일
python -m jeju_agent.cli --offline --batch examples/questions.txt   # 일괄, LLM 없이
python -m jeju_agent.cli --status                       # 데이터·LLM 상태
pytest -q                                               # 테스트
```
결과 JSON은 `outputs/`에 저장됩니다.

## 6. 오류·제약사항
| 증상 | 원인·조치 |
|---|---|
| "데이터셋 … 적재되지 않았습니다" | 해당 CSV가 data/raw·synthetic에 없음 → 파일 추가 후 다시 읽기 |
| 사이드바 source가 synthetic | 실데이터 미적재. 결과를 실제 판단에 쓰지 마세요 |
| 답변 끝에 "(오프라인 모드…)" | LLM 키 없음/장애. .env 확인. 실행 계획 패널에 폴백 사유 표시 |
| 한계에 "기본값으로 채웠습니다" | 원본 CSV에 없던 컬럼(예: 승하차유형)을 기본값으로 채움. 그 컬럼으로 나눈 비중은 보지 마세요 |
| 지도가 비어 있음 | 좌표가 없는 결과이거나 지도 타일 차단. 표·차트는 정상 |
| 장소·노선을 못 찾음 | "어떤 데이터가 있어?" 또는 list_places 결과로 이름 확인 |
| 느림 | 첫 적재 10~30초(캐시됨). 수백만 행이면 duckdb 설치 권장 |
| 한글 깨짐 | CSV 인코딩 자동 판별 실패. UTF-8로 다시 저장 |

제약: 와이파이 이용자는 표본(상대 지표), 와이파이 시간대 분석 불가, 버스 효율은 승차 수요 기준, 강우 효과는 단순 비교, 오프라인 모드는 정형 질문만.
